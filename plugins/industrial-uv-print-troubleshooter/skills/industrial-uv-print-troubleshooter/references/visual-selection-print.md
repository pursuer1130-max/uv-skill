# 扫描、框选、验证与单次打印

默认只读。扫描与打印仅在当前明确授权、材料范围核实、人员安全和现场就绪条件成立时执行。历史批准不随插件或设备迁移，状态不明时停止受影响输入；不自动重试。

## 准备

执行 LoadCheck 与本机许可检查，再用 Stage-DesktopCompat.ps1 从维护源校验并暂存四个运行文件到非 RIP 监听的本地目录。重新识别实际程序与唯一窗口；版本、二进制、布局、材料或设备变化后重新核实。通过当前环境支持的 Computer Use 启动方式打开隔离 helper 并选定真实目标窗口。每个命令 ID 仅消费一次，启动有效期为两分钟。

## 当前作业顺序

1. capture-controls 只读观察。扫描区域控制是切换操作；先读回当前勾选状态，只改变与本次目标不同的区域。关闭下拉框提交后重新捕获，核对实际选择。区域范围取自当前作业，不把示例 1~3 当作默认值。按 visual-scan-compat.md 的当前守卫执行一次已授权扫描。
2. 扫描结束后 capture-view --target-exe <当前程序>，检查本机 viewport-private.png 的清晰度和当前产品位置。画面可能包含客户图稿，只供临时观察，不随仓库或插件分发。
3. 执行 select-products <当前视图ID> <x1> <y1> <x2> <y2> --selection-authorized --target-exe <当前程序>。矩形须位于当前画布内；准备器与原生程序核对当前视图哈希、窗口大小、空闲状态、端点所属进程和前台。仅发送一次拖动，保证释放鼠标。坐标取自当前图像。
4. 再次 capture-view，核对选框覆盖目标而不含其他产品。执行 verify-product <新观察ID> --product-verification-authorized --target-exe <当前程序>，核对识别数量、位置、模板和逐件配图；非零计数本身不能证明正确。
5. capture-print-evidence --target-exe <当前程序> 取得原始日志与全部已加载模板。该记录可能包含客户名称，留在本机；共享前脱敏。将原始完整验证行用于下一步，不能用格式化树拼装日志。
6. 当前打印授权和现场条件仍成立、验证对应当前选框且数量正确后，重新 capture-controls，准备一次 print-once：

   node prepare-command.cjs print-once <当前控件观察ID> --print-authorized --operator-ready --selection-run <本次框选ID> --verification-run <框选后的验证ID> --verification-line <原始完整最新验证行> --template <当前模板名> --count <已核实数量> --target-exe <当前程序>

   helper 核对当前程序哈希、窗口大小、无活动或暂停作业、最新日志精确匹配、模板哈希、产品数、扫描参数面板，以及唯一可用且未遮挡的视觉打印按钮 17061。仅一次点击，无自动重试；命令 flags 不能代替现场事实。

7. 只读观察日志、按钮和状态。软件生成数据或报告正在打印不代表物理完成。由现场分别核实喷印、完成、介质定位、墨层和固化质量。任何结果未知时查询同一命令 ID，不重发打印。

图稿、扫描图、模板、材料或选择改变后重新验证。适配器源码、命令准备器、运行文件和隔离测试随包提供；这不代表所有软件版本、设备或材料均已通过现场验证。
